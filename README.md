# CodeBurger · 麦门人格汉堡工厂

**Feed Your Agent.**

答 5 道生活小题，组装出一只只属于你的汉堡人格，再把它喂给你的 Agent。

> 2026 麦当劳 1024 程序员创意开发大赛（M-Code）参赛作品。
> 项目由参赛者独立开发，**非麦当劳官方产品**。

---

## 它是干嘛的

不是一个点餐助手。

CodeBurger 把「汉堡」当成一种人格容器：你回答 5 道题，它把你映射到 8 种汉堡人格中的一只，
当场把这只汉堡组装出来，然后你可以把它喂给页面里的 Agent —— Agent 会因此进入专注、灵感、Bug 或摸鱼四种状态之一。

全程不需要登录，不填手机号，答案不上传。

## 怎么玩（四个屏）

| 屏 | 做什么 |
| --- | --- |
| **1 · 人格测试** | 5 道生活情境题，每题 4 个选项，约 40 秒 |
| **2 · 生成结果** | 组装出你的汉堡，摊开它的面包 / 夹层 / 装饰 / 服装 / 表情五轴 |
| **3 · 投喂** | 点汉堡喂 Agent，看它进入什么状态、说什么话 |
| **4 · 分享卡** | 导出 3:4 的 PNG，直接发朋友圈 |

**第 2 屏还能加料**：输入一个 GitHub 用户名，读取公开仓库与语言信息，
给你的汉堡加一层代码配料（TypeScript 脆片、Python 浓汤、star 招牌酱……）。
加不上也不影响后面的流程。

## 8 种汉堡人格

8 只全部是汉堡形态，靠**面包 / 夹层 / 装饰 / 服装 / 表情**五个轴区分。

| 角色 | 性格 | 一句话 |
| --- | --- | --- |
| 社牛辣椒堡 | 外向、热情、能量拉满 | 我认识的人比你刷的视频还多。 |
| 深夜摸鱼堡 | 白天关机、夜里才活过来 | 别问我白天在干嘛，我没醒。 |
| 灵感芝士堡 | 好奇心重、点子跳脱 | 刚又想出三个主意，一个都没记住。 |
| 淡定双层堡 | 稳、慢、不慌 | 急也没用，反正都要排队。 |
| 计划鸡腿堡 | 有条理、目标感强 | 我的待办事项有编号，还有优先级。 |
| 冒险鳕鱼堡 | 敢试、不怕翻车 | 没吃过的东西才值得点。 |
| 手抖薯饼堡 | 冲动、手快、小错不断 | 我不是故意的，但确实掉了。 |
| 佛系蔬菜堡 | 不争不抢、养生、慢慢来 | 都行，都可以，看你。 |

角色资产在 `public/assets/personas/`。

## 人格是怎么算出来的

**确定性映射，不是随机抽。**

1. 五道题各覆盖一个维度，选项权重只有 −1 / 0 / +1 → 得到一个五维向量
2. 对 8 个原型向量算加权欧氏距离，取最近的一个；并列时按 id 字典序
3. 同样的答案永远得到同一个人格，不随刷新变化

单测枚举了全部 **4⁵ = 1024** 份答卷，断言每份都有确定归属、8 个人格全部被命中（无死角色）。
这些答卷折叠到五维向量空间后，不同向量不超过 **3⁵ = 243** 个。两个数字指的不是一回事。见 `tests/persona.test.mjs`。

**人格测试是趣味娱乐内容，不具备心理测量学效度，不构成任何专业建议。**

## 真实 MCP 集成

项目接入了麦当劳官方 MCP 服务（`https://mcp.mcd.cn`），核查了 35 个工具的能力，
并做了真实只读调用验证。详细条款解读见 [`MCP_INTEGRATION.md`](MCP_INTEGRATION.md)。

**架构上有一条硬红线：公开网页零 MCP 调用。**

```
公开网页（谁都能玩）                WorkBuddy Skill（本地 · 真实 MCP）
  · 零 MCP 调用                       · 用使用者自己的凭证
  · 零官方数据集                       · 由使用者本人在对话里触发
  · GitHub 加料只访问公开 API           · 只调只读工具，单次调用
  · 原创虚拟配料 + 趣味映射             ← 这一层才算「个人正常使用场景」
```

《麦当劳MCP服务规则》第一条 1 明确写着本服务面向「通过**自行使用的第三方 AI 工具**」访问
「**由您授权触发的**」操作 —— 这是本地 Skill 的正当性依据。
但第三条 2 与第六条 2 对批量、高频、自动化调用有明确限制，
所以网页代所有访客调用（无论用谁的 Token）都在禁止范围内。

**官方营养数据的公开使用范围尚未获得授权，因此本项目不分发任何官方数据集。**

### codeburger-feed Skill

`skills/codeburger-feed/` 是一个可用的 WorkBuddy Skill。它读官方营养表，
把**虚拟人格**与**真实餐品营养数据**放进同一份 JSON（Burger Spec）返回。

```bash
npm run skill:demo    # 本地自检，全程不联网、不用 Token
```

Burger Spec 是本地 Skill 与网页之间的公共数据契约，定义在 `src/spec/burger-spec.ts`，
带完整校验函数。要点：**虚拟层（`source: "virtual"`）绝不允许携带营养数据**，
这是单测和 CI 都会卡的红线。

## 三层数据结构（真实与虚构严格分开）

| 层 | 内容 | 标注 |
| --- | --- | --- |
| L1 官方真实餐品参考 | 仅本地 Skill 层，需授权 | `reference` |
| L2 趣味人格映射 | 人格 → 餐品**类别**的趣味对应 | `非科学结论` |
| L3 原创虚拟配料 | 全部原创命名 + GitHub 公开数据衍生 | `virtual` |

**不把整款真实餐品的营养数据解释为某个虚拟配料的属性。** 校验函数会直接拒绝这种 Spec。

## 技术

单 Vite + TypeScript 应用，零运行时依赖。

- 人格引擎：确定性五维映射，纯函数
- 角色渲染：位图资产 + CSS 动效
- 分享卡：原生 Canvas 2D，不引第三方库，3:4 PNG
- GitHub 加料：公开 API，无 Token，失败自动降级
- 状态：`localStorage` 不落盘，答案不上传

```bash
npm install       # 遇到 esbuild postinstall 报错见下方 Troubleshooting
npm run dev       # 本地开发，端口 5180
npm run build     # 产出纯静态 dist/
npm test          # 49 条单元测试
npm run typecheck # 类型检查
npm run gate:a    # 重跑 MCP 合规取证（需要自己的 Token）
npm run skill:demo  # Burger Spec 本地自检
```

Node 版本要求 ≥ 22.6（用到 `--experimental-strip-types`）。

### Troubleshooting

某些受限 Windows 沙箱里 `npm install` 会在 esbuild 的 postinstall 报 `EBUSY`。
不要改仓库里的 `.npmrc`（那会影响所有克隆者），改用命令行参数：

```bash
npm install --ignore-scripts
```
